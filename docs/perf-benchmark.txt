Loaf performance test notes
===========================
Date:      2026-10-28, ~15:15–15:30 IST
Committed: changes in src/listing.rs, src/pane.rs, qml/FilePane.qml
           (model refactor: shared Arc rows, pre-lowered names, allocation-
           free natural sort, canvas repaint guard)

WHAT WAS TESTED
---------------
Three builds, same machine, same test folder, one at a time:

  * loaf "new"     0.2.0 (repo) target/release/loaf — with this repo's
                   performance changes, built 15:14 (all source changes
                   predate the build, QML included)
  * loaf "old"     0.2.1 (/usr/bin/loaf) — system-installed release
  * nautilus       51.1 (/usr/bin/nautilus) — reference comparison

WHAT WAS TESTED ON
------------------
Machine:  Arch Linux, kernel 7.2.11-arch1-1
CPU:      Intel Core i3-1115G4 (2c/4t, 3.00 GHz), scaling governor active
RAM:      7.5 GiB total, ~3.4 GiB available during tests
GPU:      Intel UHD (Tiger Lake GT2), Mesa 26.2.5, OpenGL 4.6
Session:  Wayland, niri compositor, ~1920x1080
Input:    ydotoold running (used to inject keyboard events)

Test folder: ~/loaf-bench/big — 12,020 entries on the real home disk
(not tmpfs): 4,000 valid 1x1 PNGs "photo_NNNNN.png" (digit-heavy names,
exercise thumbnails + natural sort), 6,000 "IMG_2026-01-NN_NNNN.jpg.txt",
1,000 Cyrillic-named files, 1,000 digit-leading "-report-N.md", 20
subfolders. Folder is left in place for re-running; delete with
`rm -rf ~/loaf-bench` when done.

HOW IT WAS TESTED
-----------------
Benchmark scripts live in docs/bench/ (fixture, open and scroll):

1. bench-open.sh <binary> loaf|nautilus [path] — cold start:
   - kills every loaf instance (pkill -x loaf) / quits nautilus (nautilus -q)
     and waits until no matching window remains, so every run is a true
     cold start. This matters because loaf is single-instance: without
     --new-window a second `loaf <path>` just hands the path to the running
     instance over D-Bus (io.github.m_uvex.Loaf) and exits — you would time
     the old binary twice.
   - spawns the app with --new-window on the test folder
   - polls `niri msg --json windows` every 10 ms until a window whose title
     contains the folder name exists — i.e. the window is mapped AND the
     listing is shown (both apps set the title to the folder name)
   - prints elapsed milliseconds, kills the app, waits 0.3 s

2. bench-scroll.sh <binary> loaf|nautilus [path] [keys] — interaction:
   - same clean start, waits for the window, focuses it via
     `niri msg action focus-window` (aborts without sending any keys if the
     compositor does not report the bench window as focused)
   - samples the app's utime+stime from /proc/PID/stat and VmRSS from
     /proc/PID/status, then sends N Down-arrow presses via ydotool
     (12 ms apart) which scroll the view in both apps, then samples again
   - reports wall time, CPU ms consumed by the app, RSS before -> after

3. Renderer parity check (fairness): loaf run once with QSG_INFO=1 —
   "Creating QRhi with backend OpenGL ... Intel ... Mesa ... vsync 16.67 ms".
   Hardware-accelerated, so loaf's auto low-power mode stays OFF (a software
   fallback would have silently switched it to the low-power profile and
   invalidated the comparison). GTK4/nautilus uses its ngl GL renderer by
   default; pin with GSK_RENDERER=ngl to be strict.

4. In-process micro-benchmarks (done while making the changes, release
   build, throwaway tests since removed from the source):
   - refilter of a 20,000-entry list, 10 repetitions: the old code path
     (per-entry name lowercasing + full deep clone of every matching row)
     took 70 ms; the new path (pre-lowered names + Arc refcounts) 7 ms
     -> ~10x faster. This path runs on every folder open, every filter
     keystroke, every hidden-file toggle and every inotify-triggered refresh.
   - natural sort of 30,000 digit-heavy names: 19 ms -> 16 ms (~15% faster),
     order verified identical between old and new implementations.

Fairness notes: both loaf versions share ~/.config/loaf (identical
settings, tab/session restore) and all three apps share the freedesktop
thumbnail cache ~/.cache/thumbnails — same warm-thumbnail state for
everyone. Laptop on AC; no CPU governor pinning (see caveats).

RESULTS
-------
A. Cold start to folder visible (bench-open.sh, ms; lower is better)

   new loaf 0.2.0:  364, 345, 435      (median 364)
   old loaf 0.2.1:  563, 538, 497      (median 538)
   new vs old:  ~30% faster median; every new-build run beat every old run.

   (An initial warm-up/validation run of the new build measured 448 ms and
   is not counted in the three above.)

   Nautilus was not timed here — same script works for it; add a run with:
     bash docs/bench/bench-open.sh /usr/bin/nautilus nautilus

B. Interaction smoke tests (bench-scroll.sh) — script validation only,
   NOT a comparison (different key counts, single runs):

   loaf (new):     30 keys, 1135 ms wall, 32 ms CPU, RSS 189452 -> 192776 kB
   nautilus:       10 keys,  377 ms wall, 18 ms CPU, RSS 166692 -> 169220 kB
   (ydotool's per-key daemon round-trip dominates wall time; the CPU number
   is the meaningful one. Run both apps with the same key count, e.g. 300,
   before comparing.)

C. In-process micro-benchmarks (see above): refilter ~10x faster
   (70 ms -> 7 ms per 10 refilters of 20k rows), natural sort ~15% faster.

CAVEATS
-------
- 3 runs per app is directional, not statistically solid. For real numbers
  use hyperfine (no system install, via nix):
    nix run nixpkgs#hyperfine -- --warmup 3 --runs 10 \
      'bash docs/bench/bench-open.sh target/release/loaf loaf' \
      'bash docs/bench/bench-open.sh /usr/bin/loaf loaf'
- 10 ms poll resolution + compositor scheduling add a few ms of jitter.
- Page cache was warm during all runs (folder had just been written);
  expect slower absolute numbers on a truly cold cache for all apps.
- The installed 0.2.1 is newer than the repo's 0.2.0 base, so part of the
  measured gap is version drift, not just the performance changes.

HOW TO REPRODUCE
----------------
  bash docs/bench/loaf-bench-fixture.sh        # rebuild fixture if gone
  cargo build --release                           # in the repo
  bash docs/bench/bench-open.sh target/release/loaf loaf
  bash docs/bench/bench-open.sh /usr/bin/loaf loaf
  bash docs/bench/bench-open.sh /usr/bin/nautilus nautilus
  bash docs/bench/bench-scroll.sh target/release/loaf loaf ~/loaf-bench/big 300
  bash docs/bench/bench-scroll.sh /usr/bin/nautilus nautilus ~/loaf-bench/big 300

Per-frame render timing (scrolling smoothness):
  QSG_RENDER_TIMING=1 target/release/loaf --new-window ~/loaf-bench/big
  (each frame prints its sync/render/swap ms; compare against 16.6 ms)
